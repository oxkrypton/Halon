## 二、 四大模块与技术栈

整个系统全用 **Go** 写，分成 4 个部分，各司其职：
### 1. Gin 网关（干苦力的保安：负责转发与记账）
- **用什么写**：`Gin` + Go 标准库 `ReverseProxy` + `sync.Map`。
    
- **干什么活**：
    1. **拦请求**：请求进来先过 Gin 的中间件。查内存里的黑名单、算限流，不合规直接拒掉。
    2. **转请求**：合规的请求，用 `ReverseProxy` 转发给后面的业务微服务（如 User、Wallet）。
    3. **记流水**：顺手把请求的耗时、状态码、报错内容抓下来，丢进 Go 的 `chan`（通道）里，**绝不卡住主流程**。
    4. **留后门**：在 `9090` 端口开几个内部接口（比如 `/admin/rules`），专门给 Agent 调用，用来随时修改内存里的黑名单和限流配置。

### 2. 数据库存储（账本：负责存流量日志）
- **用什么写**：Go 后台协程（`Goroutine` + `time.Ticker`）+ `PostgreSQL`（配合 GORM Gen）。

- **干什么活**：
    1. **攒批写入**：后台协程从 `chan` 里拿日志，攒够 500 条或者每隔 1 秒，一次性批量写进数据库，防止把数据库写崩。
    2. **分表省空间**：
        - **基础表（`base_logs`）**：所有请求都记，只记 IP、路径、状态码、耗时（体积小，方便算总账）。
        - **详情表（`error_body`）**：只有当请求报错（状态码 $\ge 400$）或者特别慢（$>1$ 秒）时，才把完整的请求参数（`ReqBody`）和返回结果（`RespBody`）存下来，留给 Agent 破案。

### 3. Go 流量分析 Agent（监控室大脑：负责查账与发号施令）
- **用什么写**：Go 原生代码写循环 + 大模型 API（DeepSeek / OpenAI）。

- **干什么活**：
    Agent **不在网关里攔截请求**（因为大模型太慢），它在后台独立运行（比如每分钟跑一次，或者网关报错多了喊它一下）。手头有两类工具函数（Tools）：
    1. **查账工具（读数据库）**：直接跑写好的 SQL，查出“最近 5 分钟哪个接口报错最多”、“哪个 IP 在疯狂刷接口”、“报错的具体返回值是什么”。
    2. **动手工具（调接口）**：大模型看完数据得出结论后，自动调用函数：
        - 发现黑客刷接口 $\rightarrow$ 调 Gin 的 `/admin` 接口，把该 IP 加进黑名单。
        - 发现某个接口被打爆 $\rightarrow$ 调 Gin 接口，把该接口的限流调严。

### 4. K8s 容器环境（云原生底座：负责管服务器）
- **用什么写**：`Docker` + `Minikube`（本地 K8s）+ `client-go`（Go 操作 K8s 的官方库）。
    
- **干什么活**：这就是你往“云原生”靠拢的核心：
    1. **自动发现服务**：后端微服务的 Pod 重启或扩容后 IP 会变，Gin 网关通过 `client-go` 自动监听 K8s，更新转发地址，不用手动改配置文件。
    2. **赋予 Agent 操作容器的能力**：如果 Agent 查日志发现，3 个 `user-service` 容器里只有 1 个一直在报 `500` 错误（说明这个容器卡死了），Agent 直接用 `client-go` 通知 K8s 重启这个故障容器，或者在流量太大时自动把容器数量从 2 个扩到 4 个。

## 三、 项目一句话总结
- **这是个什么东西？**
    一个跑在 K8s 里的 Go 语言网关，外挂了一个能自己看日志、自己处理故障的 AI 运维助手（Agent）。
    
- **它是怎么工作的？**
    **Gin 网关**在前面毫秒级转发请求，并把流量日志异步存进 **PostgreSQL**；**Agent** 在后台定期查数据库分析日志，一旦发现有黑客攻击或者某个后端容器挂了，就自动调用接口**改 Gin 的拦截规则**或**让 K8s 重启/扩容容器**。
    
- **为什么适合做毕设？**
    1. **纯后端硬核闭环**：不用写复杂前端页面，全套 Go + PostgreSQL + Docker + K8s，完全贴合你的日常技术栈。
    2. **好演示、好答辩**：答辩时开个脚本模拟攻击或故意弄挂一个服务，评委能亲眼看到“日志入库 $\rightarrow$ Agent 查出原因 $\rightarrow$ 网关自动拉黑 IP / K8s 自动重启容器”的全自动过程，非常直观。
